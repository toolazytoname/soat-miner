# RTX 3090 Pearl source experiment

This fork starts from `blindrun/soat-miner` revision `48defc8dcb697cb64d8d1702c35efb57112b57ac`, under the retained MIT license. The upstream project contains actual CUDA Pearl kernels and a Kryptex client. The Windows experiment builds native SM86 SASS; it does not need a Blackwell GPU.

Status: native SM86 builds and complete-transcript GPU checks pass on the RTX 3090. A bounded live probe through certificate- and hostname-verified TLS completed with 3 accepted shares and 0 rejected shares. No production backend switch or convincing speed improvement is claimed. See [measured results and limits](PRL3090-RESULTS.md).

## Build on the Windows workstation

The project uses its own `.venv` for CMake/Ninja. Versions are pinned in `requirements-build.txt`. MSVC is installed under `D:\Apps\VSBuildTools2022`; the checksummed portable NVIDIA compiler/runtime/CRT/CCCL/NVVM components are under `D:\Apps\CUDA\13.1.1`. No global Python packages are required.

```powershell
& 'D:\Apps\PowerShell\7\pwsh.exe' -NoProfile -File .\tools\build_prl3090_windows.ps1 -GpuTests
```

This command only builds. It does not start mining or use the GPU for tests. GPU tests are registered under the `gpu` CTest label and must be run separately after checking that the GPU is free. Use a thermal/power guard for all measurements.

## Measurement rules

Keep the same 220 W power cap and compare at thermal steady state. Verify the hashrate unit (MAC/s) and the complete proof path; the fastest isolated GEMM is not necessarily the fastest paid work. Record the revision, binary checksum, chosen shape/tile, warm-up, temperatures and invalid/stale work. Compare an unchanged baseline before and after an experimental variant.

The upstream Pearl pool client uses plain TCP. The existing mining route uses TLS to `prl-hk.kryptex.network:8048`; a validated TLS transport is required before a live switch. Use the same public wallet and payment mode. The first-payout-threshold stop rule, manual stop and original-power restoration must survive the migration.

## Files and records

Source stays in this repository. Build outputs are ignored under `build/`; experiments and receipts go to `D:\AI\Playgrounds\soat-miner\20261028-prl3090`. Public source publication must retain upstream and third-party notices. Do not include local wallet configuration, caches, logs or binaries in source commits.

## Guarded GPU work

Run `tools/run_guarded.py` from an elevated interactive Windows task. It obtains the same named mutex as the existing KRig supervisor, refuses other GPU applications, limits experiments to 220 W, monitors core/hotspot/memory temperatures, yields to new GPU processes, and restores the original power cap. It only stops its own direct child. Run the test executable directly rather than wrapping GPU CTest children inside the guard. A `stop.request` file in the new run directory requests a manual stop. CPU processes run below normal priority; driver clocks and fans remain automatic.

`tools/run_pool_probe.py` connects the upstream TCP client to a **loopback-only** relay with mandatory certificate and hostname verification, a TLS 1.2 minimum and no plaintext fallback. Pass `--config` with a local JSON containing `pool`, public `wallet` and `worker`. A public receive address is sufficient: never provide a private key, seed phrase or wallet password. Pass `--deadline-state` with the existing experience JSON to retain its original `MiningDeadline`. The probe checks the public pool API and stops at the first payout threshold or recorded payout. It does not exchange currency or sign wallet transactions.

## Experimental configuration and diagnostics

Add `-AmpereCandidates` and a separate `-BuildDirectory` to the build command to include three optional SM86 tile candidates. They are disabled by default and are skipped on other architectures. The arithmetic and proof protocol are unchanged. Kernel tests now exercise K64 explicitly instead of silently rerunning K32.

Set `SOAT_PEARL_PROFILE=1` only for diagnosis. Sampled CUDA events report preparation, GEMM, scan, readback and attempt wall time after the existing synchronization; no new synchronization is added per sample. Diagnostic timing is disabled in normal mining. `SOAT_PEARL_SHAPE` and `SOAT_PEARL_TILE` can pin a comparison, and all active pins are recorded in guard receipts. Do not quote autotuning's device-only candidate rate as live hashrate.

### Exact candidate experiments

`SOAT_PEARL_TILE` is normally a name prefix; start it with `=` for an exact name, for example `=ampere fixed s2 g8 k64`. The optional fixed specialization uses the existing mining K=2048 / rank=128 and preserves transcript semantics. It is not enabled in default builds. See the resource and correctness evidence in `PRL3090-RESULTS.md`; no speedup is asserted before a matched thermal comparison.

Set `SOAT_PEARL_PROFILE` to exactly `1` to sample stage timing. Leave it unset or set to `0` for an uninstrumented comparison. `test-pearl-kernel-resources.exe` reports compiled resources and theoretical occupancy; it is not a hashrate benchmark. Run GPU test executables directly through `run_guarded.py`, not by wrapping a CTest parent that spawns GPU grandchildren. Use `-LE gpu` for CPU-only CTest checks when the optional GPU tests were built.
